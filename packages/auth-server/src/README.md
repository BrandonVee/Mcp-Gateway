# Auth Server 源代码目录规范

根目录只保留执行入口 `index.ts`。启动阶段负责迁移、系统配置、管理员引导和基础设施就绪检查；HTTP 路由由 `application/app.ts` 统一装配。功能模块的导入不会启动 HTTP 服务。

## 目录与职责

| 目录                                                         | 职责                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------- |
| `application/`                                               | 启动编排、应用工厂、全局 HTTP 中间件及注册顺序          |
| `modules/admin/`                                             | 管理员身份与审计中间件、管理请求校验、按资源拆分的路由  |
| `modules/identity/`                                          | 用户认证、会话持久化、注册、邮箱校验和管理员引导        |
| `modules/oauth/`                                             | 平台 OAuth 授权、令牌、客户端、签名密钥和元数据         |
| `modules/access/`                                            | 用户与逻辑端点的授权关系                                |
| `modules/connections/`                                       | 浏览器连接中心及旧副本池的连接生命周期                  |
| `modules/upstreams/`                                         | 独立上游配置、凭据解析、OAuth 刷新、注册表和连接探测    |
| `modules/system/`                                            | 系统设置、版本目录与应用更新编排                        |
| `modules/monitoring/`、`modules/audit/`、`modules/topology/` | 监控、管理员操作审计和运行拓扑                          |
| `infrastructure/database/`                                   | PostgreSQL 连接、版本迁移、稳定锁命名空间和领域表模型   |
| `infrastructure/docker/`、`cache/`、`mail/`、`security/`     | 外部系统通信和安全实现                                  |
| `shared/http/`、`security/`、`serialization/`                | 与具体路由无关的 Cookie、Origin、限流、校验和序列化工具 |

## 依赖与扩展规则

- 路由负责解析请求、调用业务服务及生成 HTTP 响应；身份、凭据、锁和 DTO 查询能力放在对应服务或工具中。
- 跨模块调用引用具体能力，禁止业务服务反向导入路由装配器；公共工具不依赖业务路由。
- 管理路由使用 `AdminRouter`，审计身份通过类型化上下文传递，不能使用强制类型转换绕过身份检查。
- 新管理资源添加到 `modules/admin/routes/`，由管理装配器注册；公共浏览器写请求由连接中间件统一保护。
- 表模型按身份、OAuth、上游、可观测性和系统划分。数据库表名、约束与迁移历史是持久化契约，重命名代码文件不意味着重建表。
- 上游认证列通过工厂生成，每张表获取独立 Drizzle builder，不能复用可变列对象。
- `infrastructure/runtime/paths.ts` 统一处理源码运行与 `dist/index.js` 打包运行的迁移目录差异。

## 安全与并发约束

- 请求日志只记录路径和元数据，禁止记录 OAuth 查询参数、请求体、认证头或密钥。
- 浏览器身份同时检查不可变用户 ID、用户名、账号状态与认证版本；跨标签页写请求沿用 `x-session-identity` 校验。
- 会话 Cookie 的名称、有效期、HttpOnly、SameSite、Secure 和删除路径由一个工具维护。
- 凭据归属为 `system` 或 `user:<id>`。普通用户不能覆盖系统授权；端点分组不持有独立上游的业务凭据。
- 凭据解析遵守“端点 → 上游 → 用户 → 授权 → 凭据”的锁顺序。锁命名空间不能随意改变，滚动升级时必须保持一致。
- OAuth 回调需要在兑换后再次验证待处理状态；断开连接、认证变更或账号撤销不能被迟到的回调复活。
- 对外目录和探测结果只返回状态信息；密钥与令牌仅在后端解密并注入指定上游。
- 连接探测使用点击时的表单草稿：当前地址、请求头和值前缀优先，新填密钥优先；密钥留空时沿用已保存密钥。探测只读取现有凭据，不保存配置、不刷新或改写正式令牌。只有手动保存才改变正式调用。

本包启用 TypeScript strict、`noUnusedLocals` 和 `noUnusedParameters`。这些是静态约束，不替代运行验证。
